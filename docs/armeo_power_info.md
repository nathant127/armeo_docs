# Limitations to the Control Method

The model used to control the armeo power does not provide all the information and control methods that would be avaliable on a typical robotics device and as such there are some limitations that had to be worked around in order to control the Armeo.

## Provided Signals

The Armeo provides 19005 different signals that can be read from, most of these are blocks that only serve as an inbetween between other blocks such as "add" or "rad2deg" and as such can be ignored. However there are a number of parameters that report useful info about the robot state.

The full list of signals can be found [Signals](/data/armeo_signals.csv)

Some of the signals were investigated and out of those signals the main ones are listed below

| Signal Name | Unit | Description |
|-------------|------|-------------|
| Output/SoftwareSignals/JointAngle/s1-7 | rad | 7 signals, reports live joint angle of each joint |
| Output/SoftwareSignals/EndEffector/s1-3 | m | 3 signals, reports live cartesian end effector position (xyz) |
| Kinematics/Jacobian EE/s1-36 | m/s or rad/s | 36 signals, jacobian for the end effector, in the base frame, col major ordering|
| Output/SoftwareSignals/JointVelocity/s1-7 | rad/s | 7 signals, reports live joint velocity of each joint |

Note that there are some signals that you might expect to see that are missing, primarily end effector orientation, end effector velocity and the transforms for forward kinematics.

The Transforms can be calculated from the estimated DH Parameters, the end effector velocity can be calculated from the jacobian and joint velocities but the end effector orientation cannot be calculated.

## Operation Modes

The Armeo can be controlled via a number of operation modes provided in the model, not all of the operation modes were explored but their purposes can be guessed from the names.

The Full list of Operation Modes can be found [Operation Modes](/data/armeo_operation_modes.csv)



Explored Operation Modes:

| OM Name | OM Number | OM Description | Further Info |
|---------|-----------|----------------|--------------|
| OMMobilization| 2 | Allows Joint space position based control, does not allow user to move robot | [Mobilization](/docs/mobilization_mode.md) |
| OMServiceMode| 5 | Allows a set of basic hardcoded movements at a constant velocity | [Service](/docs/service_mode.md) |
| OMEStopTest | 6 | Default operation mode, used during initialization | |
| OMWatchdogTest| 9 | Required for initialization process, likely related to Power | |
| OMDirectTorque |10 | Allows Joint Space torque control | [Direct Torque](/docs/direct_torque_mode.md) |

The operation modes can be swapped between by setting the parameter `Input/OperationMode/OperationMode` to the respective Number for that Operation Mode

These control modes have a number of limitations that are further explained in their specfic documents, but the primary gap is a lack of an operation mode that provides joint space velocity control and a lack of an operation mode that provides cartesian space position control.

- Cartesian space position control can be achieved using inverse kinematics and mobilization mode.
- Joint space Velocity control could be achieved using direct torque mode and joint velocity feedback with some kind of PID controller.
